# Engine Viewer Skill

The public viewer engine `@hcm/engine` (`packages/engine`): a data-driven historical map of one city, embeddable by any city owner. Public contract: `docs/ENGINE_API.md` (config.js, `<hcm-map-viewer>`, the JavaScript API, the URL hash, the City Manifest v1, versioning). The interfaces the M1 workstreams build on (MapPort, the viewer store, telemetry, UI inventory, module ownership, change requests): `docs/research/M1-interfaces.md`. Architecture: `docs/ARCHITECTURE.md` → *Engine (public viewer)*; plan: `docs/research/PLAN.md` → *Engine*. M1 built it; how the parts were joined is `docs/research/M0-handoff.md` §10j.

## Where the code is

- `packages/engine/src/index.ts`: the release facts (`ENGINE_VERSION`, `MAPBOX_GL_VERSION`), `mount`, `defineElements` and the auto-boot, wired to the browser. `packages/engine/src/mount.ts` makes every decision behind a DOM-free `MountEnvironment`, so its node tests drive it with fakes.
- `packages/engine/src/config/load.ts` (configuration, manifest fetch with a 15 s timeout, retries on network errors and 5xx), `packages/engine/src/core/` (the viewer store: `store.ts`, `boot.ts`, `state.ts`, `timeline.ts`, `url-sync.ts`, `map-sync.ts`, `map-specs.ts`, `preferences.ts`), `packages/ui/src/map/` (the MapPort and its Mapbox adapter, the `@hcm/ui/map` entry shared with the admin since CR-M2c-1 of `docs/research/M2c-interfaces.md`), `packages/engine/src/telemetry/` (consent, lazy analytics, crash reports).
- The viewer's Lit elements (`<hcm-map-viewer>`, the timeline, the sheets, the lightbox, About, the error card) live in `packages/ui/src/viewer/` under the ownership override (one owner per tag, next to the kit they are built from). `@hcm/ui` cannot import the engine, so `packages/ui/src/viewer/store-port.ts` mirrors the store's shape and `mount.ts` checks at compile time that the real store satisfies it.

## Contract

- **Build**: `npm run build --workspace @hcm/engine` runs `packages/engine/vite.config.ts` twice (`dist/engine.mjs` with its lazy chunks, then `--mode iife`: `dist/engine.iife.js` with the global `window.HistoricCityMap` and its extras `extra-<name>-<hash>.js`; `dist/engine.css`), then `fonts:copy` puts the kit's self-hosted fonts and their licences into `dist/fonts/`; a site copies every file of `dist/`. `mapbox-gl` is **external**: the engine reads the page's global `mapboxgl`, which pages load as Mapbox GL JS **3.34.1** from `api.mapbox.com` (`MAPBOX_GL_VERSION`). Never bundle it or import it.
- **Extras on demand** (`docs/ENGINE_API.md` → *Extras on demand*, DECISIONS §186): code no first paint needs goes into an IIFE extra, not into `engine.iife.js` (its budget is the scarce one). A new extra is a key in `packages/engine/src/extras/imports.ts` (a dynamic import, as the tests run it) and the same `global` in the `extras` list of `packages/engine/vite.config.ts` (the build refuses keys that differ), its callers reach it only through `extraImports`, and a budget row `extra-<name>` in `check_bundle_budget.py`. It takes Lit and `@hcm/shared` from the host: a binding it imports that `src/extras/host-lit.ts` or `host-shared.ts` does not list stops the build, and so does a copy of Lit, the catalogues or zod. A Vite library build with two formats is one bundle (plugins see it once), so a per-format swap of a module needs its own run (`vite build --mode iife`). Its failure must reach the visitor as a message to try again (`error.extraLoad`), and the loader retries on the next wish.
- **Config**: `window.HistoricCityMapConfig = {cityId?, manifestUrl? | manifest?, container?, lang?, engineBase?}`, validated with `engineConfigSchema` from `@hcm/shared` (exactly one of `manifestUrl` and `manifest`; the inline manifest is the starter kit's static mode). Both builds auto-boot into `container` (default `#historic-city-map`; the city pages load `engine.mjs`, CR-6); a missing or invalid config shows an instructive error card (scenario V17). The engine finds its own folder (for `fonts/`) from `import.meta.url`, or from the running script in the IIFE build, where Rolldown empties `import.meta` (`engineBaseOf`).
- **JavaScript API**: `HistoricCityMap.mount(element, config)` returns a controller `{ready, setYear, toggleLayer, setOverlayOpacity, openPhoto, openPoi, setLang, openCompare, setComparePosition, closeCompare, setMapLabels, destroy}`; the element `<hcm-map-viewer>` fires `hcm-ready`, `hcm-error`, `hcm-layer-change`, `hcm-overlay-change`, `hcm-photo-open`, `hcm-poi-open`, `hcm-compare-change`, `hcm-map-labels-change` (scenarios V21, V06, V31).
- **Data**: the viewer fetches only the static `manifest.json` and the photo WebP files from the public bucket (`gs://<proj>-public/cities/{city}/...`); the Bucharest site reads the bucket's manifest when its build names the bucket (`HCM_PUBLIC_BUCKET`, `site.json` → `publicManifest`, `scripts/site/src/public-manifest.ts`), else it bundles the seed snapshot (`DECISIONS-for-review.md` §51e, §55a). It **never reads Firestore** and loads no Firebase SDK for data. The analytics SDK (GA4 only, never Performance Monitoring) loads lazily, only with a `measurementId` in the manifest **and** the visitor's consent, and never sees the hash (`firebase/analytics_and_crash_skill.md`).
- **Manifest**: City Manifest v1, `manifestSchema` in `packages/shared/src/schemas/manifest.ts`, every object strict. Before the schema, `checkManifestCompat` refuses another `version` and a `city.engine.minVersion` newer than the engine; then `validateManifest` returns `{path, code}` issues whose codes are `validation.*` i18n keys. A failure shows a localized error card, never a blank map (V01); an invalid manifest's card names its first issue (`issuePath: <localized validation message>`, from the error's `issuePath` / `issueCode` params). A configuration error card speaks the address's language first (`?lang=` or `#…&lang=`), then the configuration's.
- **A photo's date and source** (`docs/research/photo-date-source.md`): `month`, `day` and `source` are optional in v1; `photoDateText` reads `dateText`, then the date at its precision through `Intl` (`formatPhotoDate`), then the years. The timeline reads only the year; the source is an `externalLink`, never HTML.
- **URL hash v1**: `encodeHash` / `decodeHash` in `packages/shared/src/url/hash.ts` (`#zoom/lat/lng[/bearing]&layers=&opacity=&op=&cmp=&sw=&labels=&photo=&lang=`), defensive and clamped; the legacy `#zoom/lat/lng/rotation/!a3!p2` opens its view and is rewritten. Decode with the manifest's overlay ids (`HashLimits.overlayIds`) so `op=` entries of unknown overlays are dropped. The old single `opacity=` applies to the visible historical layers only (apply the hash's `layers=` first); `op=` entries win. The store writes the hash at most every 300 ms and never over a hash the address gained in between (a typed link or history navigation wins). A camera move that is the visitor's position (Show my location's `store.flyTo`) never reaches the hash: `ViewerState.hashView` keeps the view the hash had until the visitor moves the camera or a hash is applied (S-V10-BAD-POSITION-NOT-IN-LINK); a privacy test searches the address and the shared link too.
- **Map labels** (V31; `docs/ENGINE_API.md` → *Map labels*): the basemap's own text, not an overlay. `state.mapLabels` (`packages/engine/src/core/map-labels.ts`: `shown`, `defaults`, `available`) follows what the mounted map answers through `ViewerMapPort.getBasemapFlag`, never the style's URL: a custom style has no switch and is never written. `MapPort` itself stays lean: `createViewerMapPort` (`packages/ui/src/map/viewer-map.ts`) adds the viewer/compare methods so the admin's bundle carries none of them, and the admin's `withMapProjection` (`packages/admin/src/map/projection.ts`) adds lon/lat ↔ screen CSS px so the engine IIFE never ships them (DECISIONS §146 / LESSONS 551). Map-label words are the catalogue `@hcm/shared/map-labels` for the same reason. Absent `labels=` means the city's default on `hashchange` too (the encoder omits a default). `MapSync` writes on either map, only what differs; a link's choice goes into `mapOptions`' `config`, so it never flashes. Standard's transit stations (`showTransitLabels`) follow the points of interest switch (`transitLabels` in `@hcm/shared/map-labels`: written only where the map has `showPointOfInterestLabels`, an explicit `basemap.config` value stands at the city's default; the owner's report of 2026-11-08); `showPlaceLabels` stays the city's.
- **Overlays** (PLAN Addendum 3): every historical layer, the photos (`PHOTOS_OVERLAY_ID`) and every POI category is an overlay with `visible` and `opacity`, built and updated only through the pure overlay model of `@hcm/shared` (`packages/shared/src/overlays/model.ts`: `overlaysFromManifest`, `withOverlayOpacity`, `withOverlayVisibility`, `withHashOpacity`, `hashOverlayOpacity`). Paint property names come only from `overlayOpacityPaint` and `rasterAdjustmentPaint` (`packages/shared/src/overlays/paint.ts`). Layer ids, `photos` and category ids are one namespace, enforced by the manifest schema.
- **POIs**: `poiCategories[]` and `pois[]` (GeoJSON Point, LineString or Polygon) in the manifest; the store hands the map only the POIs `poiInYear` keeps for the timeline stop (all at "today"); an icon the engine does not bundle is drawn as `poiIcon`'s default pin; details open in the same sheet as photos (`poiYearsText`: lifespan, or `poi.yearSeen` when only the plan year is known). Lines and area outlines stand on a white casing layer (`hcm-poi-<id>-casing`, 90 % of the overlay's opacity) so they stay legible on a satellite basemap; every opacity paint property of the seven layers still comes from `layerOpacityPaint` (`DECISIONS-for-review.md` §77b, lesson 307: probe a drawing over a dark ground too).
- **Stories** (M17, `docs/research/M17-stories.md` §5; V50): `stories[]` in the manifest, the sheet `stories` (`selectedStoryId`: null shows the list) opened by `openStory` (the menu's Stories, a photo's or a place's sheet, `#story=<id>`), which also moves the timeline to the stop nearest the story's first year (`withStory`), except from a hash that also carries `layers=`: the link's layers win (lesson 446). `<hcm-stories>` walks `parseStory`'s blocks into Lit templates (`renderParagraph` for a paragraph, a figure of a manifest photo), never HTML; a figure of a photo the manifest does not list is left out, and only a placed photo's figure opens on the map. The IIFE carries every viewer text: keep a feature's words few and reuse the catalogue (`poi.years` gives a story's span).
- **Element**: the viewer is a Lit custom element `hcm-map-viewer`, no decorators, registered by an idempotent `define…()` function (`web/ui_m3_adaptive_skill.md`). The engine sets `mapboxCssUrl` (mapbox-gl.css is linked inside the shadow root), `engineVersion` and `bootError`, and connects the store with `attach(store, controller)`; `mapContainer` is the stable `<div>` the map mounts into. Public events come from store transitions; a slider drag announces once, on release.
- **Store actions the UI uses** (`docs/research/M1-interfaces.md` §6 plus CR-8 and CR-17): `setView` only records the map's view (the `moveend` path), `flyTo(view)` moves the camera ("show my location"), `logShare()` sends the `share` event after a completed share or copy; `destroy()` also destroys the map exactly once and telemetry.

## Map

- **One seam**: the core (state, timeline, controller, manifest → layer specs) talks only to `MapPort` (`packages/ui/src/map/map-port.ts`, M1; the exact interface is `docs/research/M1-interfaces.md` §4). `packages/ui/src/map/mapbox-adapter.ts` is the only file that touches `mapbox-gl`; dependency-cruiser enforces it. The core is tested against `FakeMap`, the adapter in Vitest browser mode against the real `mapbox-gl@3.34.1` (dev dependency, exactly the CDN version) with a local style and synthetic tiles. `FakeMap.flyTo` fires no `moveend`, but Mapbox does, synchronously: `flyTo` and `easeTo` first stop the move under way (its `moveend` at once) and a jump fires its own before returning, so a store test of anything that counts `moveend`s wraps the fake's `flyTo` to fire them (`asMapboxMoves`, `store-locate.test.ts`). Whatever is drawn on "the map" for the visitor (the blue dot, Show on map's ring) is state that `MapSync` draws on every map of the view, never a direct call to the main map's port (LESSONS 482).
- **Basemap**: Mapbox Standard Satellite. Historical rasters go into the `middle` slot; 3D buildings are off while a historical layer is shown, and only when the style has the `basemap` import.
- **Sprites** are drawn on a canvas (`packages/ui/src/map/icons.ts`, nothing fetched): photo markers are 22 CSS px discs with a bearing pointer, clusters 30 px; a POI glyph is drawn with the kit's icon font, whose family is `ICON_FONT_FAMILY` of `@hcm/ui` (`HCM Material Symbols Rounded`), never a hard-coded name (a wrong name silently draws every POI as a dot). A sprite drawn later replaces its placeholder with `updateImage`, which does not repaint an idle map in Mapbox GL 3.32: follow it with `triggerRepaint()`, or a glyph whose font arrives after the map settled stays invisible until the visitor moves the map (`docs/LESSONS.md` #21, `S-V24-BAD-ICON-FONT-LATE`).
- **Settings**: `performanceMetricsCollection: false`; the Mapbox logo and attribution are always visible (also collapsed on compact, scenario V18). Where the map shows, nothing opaque covers them; the modal surfaces draw above them (the modal layer has z-index 30, above Mapbox's corners' 2: the Pixel 9 Pro review, P3, found the credits drawn over the lightbox, and a copy of them in a legal bar and at the foot of About taking 40 to 80 px of every surface on a phone). While a modal sheet is open, Mapbox's bottom corners move into the part of the map it leaves in view: above a bottom sheet's top edge, beside a side sheet (`legal-lift.ts`: a ResizeObserver on the open modal sheet's surface, through child shadow roots, sets `--hcm-legal-lift-bottom|left|right` on the frame; the sheet's height changes with its detent and a drag, which the viewer never knows); under the sheet's scrim they show like the rest of the map. The lightbox and a full-screen dialog hide the whole map, so nothing there needs a credit; a centred dialog leaves the corners in view. The layout is an inner grid `.viewer` of one cell (never the host, whose `display` a page may set): the frame and the modal layer above it (`viewer-legal.ts`, `viewer-render.ts`; `docs/LESSONS.md` #23, #604). The tour checks one visible logo and one attribution wherever any of the map is in view, uncovered or under nothing but a translucent scrim (`mapSeen`, `probeLegal` in `e2e/support/layout-probe.ts`). Floating controls keep the map's bottom 42 px free (`--hcm-map-chrome`: the collapsed attribution plus M3's 8 px) and stack 8 px apart (`web/ui_m3_adaptive_skill.md`). Mapbox writes its UI strings (the canvas's name, the logo link, the attribution toggle) once, when its controls are created: a language switch reaches them through `MapPort.setLocale`, which rewrites them in the map's container and calls `setLanguage` for the basemap's labels (`mapboxLanguage`: the viewer's code, `zh` as `zh-Hans`; `relabelMapbox` in `packages/ui/src/map/lifecycle.ts`; CR-22, `S-V11-BAD-MAPBOX-LABELS`). The engine bundles no catalogue: the store commits a language only once its texts are fetched (`core/catalogues.ts`, the latest choice wins), the boot fetches the first beside the manifest, and the viewer renders no text before (its one bilingual card when none can be fetched).
- **Sources**: `mapbox://` tilesets, `xyz`, and `pmtiles` (M12, `docs/research/M12-own-tiles.md`: the project's own bucket, read by `packages/ui/src/map/pmtiles-source.ts` through Mapbox GL's custom source: one `Range` a tile, no library; never a bare URL, which makes GL fetch a provider script from its own host; a server without `Range` fails that layer alone, V32; a tile the archive leaves out is a transparent `ImageData`, never `null`, which Mapbox GL draws with a recycled texture of an earlier tile, lesson 496); each layer has `minzoom`, `maxzoom`, `bounds` and opacity from the manifest; the map stacks the layers by date, the newest on top, whatever the admin's `order` (`rasterSpec` passes the year as the map's `order`; the main map and compare both draw through `MapSync`; DECISIONS-for-review.md §133d).
- **One map per view** (cost): Mapbox bills map loads. Swipe compare (M4) creates its second map lazily and destroys it on exit; a compact window hides it for `COMPARE_PARK_MS` (a minute) before destroying it, so a phone turned back and forth reuses it (the 2026-10-24 review, `DECISIONS-for-review.md` §57c); the e2e map-instance counter asserts it. The chooser leaves out what the main side shows (`compareChoices`), keeping the side compared now. Compare is the engine's own (no `mapbox-gl-compare`, `DECISIONS-for-review.md` §52a, built in §55): the store keeps `compare` (`{layerId, position}`, `packages/engine/src/core/state.ts`; the mode follows the window class: `toggle` below 600 px, where `displayedOverlays` swaps the one map's historical layers, else `swipe`), the hash carries `cmp=`/`sw=`, and `packages/engine/src/core/compare-driver.ts` fetches the lazy chunk (`packages/engine/src/compare/compare.ts` → `compare-<hash>.js`, budget `ENGINE_CHUNK_BUDGETS` of `scripts/ci/check_bundle_budget.py`) once the map is ready. The chunk's session (`packages/engine/src/compare/session.ts`) puts `<hcm-compare>` (`@hcm/ui/viewer/compare`, never `@hcm/ui`'s root) after the map's container and, in swipe mode, mounts the second map in it (inert, pointer-transparent, clipped right of the divider), drawn by its own `MapSync` from `comparedState`, its camera linked by MapPort's `move` (`packages/engine/src/compare/camera-sync.ts`). The legal line stays the viewer map's (its controls sit above the second map; the bar credits the compared layer). `packages/engine/vite.config.ts` keeps what the chunks share in `engine.mjs` (`preserveEntrySignatures: 'allow-extension'`; Vite's library default split a third chunk). Contract: `docs/research/M4-interfaces.md` §3 and CR-M4-16; `docs/ENGINE_API.md` → *Compare*; tests: `packages/engine/test/compare/`, `packages/ui/test/viewer/compare/`, `e2e/specs/viewer/compare.spec.ts`, the tour's journey `compare` (`e2e/tour/compare-states.ts`).
- **Layers on one GeoJSON source**: a `circle` or `symbol` layer draws at every vertex of a polygon or line in its source, so it carries a geometry-type filter (`geometryIs('Point')` from `packages/ui/src/map/pois.ts`, `['in', ['geometry-type'], ['literal', ['Point']]]`, as Show my location's dot over its accuracy circle; `docs/LESSONS.md` #488, `S-V10-BAD-ONE-DOT-ONLY`); test what each layer renders, not only the source's features.
- **No WebGL**: `mapboxgl.supported()` false or a lost context shows a fallback card; the photo list still works (scenario V02).
- **Error card and visitor copy**: an M3 error container (`error-container`, `on-error-container` text and icon) with Retry as a filled tonal button with the refresh icon. Errors a visitor can meet say what happened and what to do in plain words, never "manifest", "WebGL", "JSON", "engine" or "tiles"; only `error.config.*` (a misconfigured page) speaks to the city owner (`docs/LESSONS.md` #26; `S-V01-HAPPY-ERROR-CARD`, `S-V01-BAD-PLAIN-WORDS`).
- **Skip link and lists**: the skip link is the first Tab stop and shows at the map pane's corner, past a docked leading pane, never over its heading (`S-V14-HAPPY-SKIP-LINK-CLEAR`). A photo list row is an M3 list item: title body-large, date body-medium supporting text (14 px) that wraps (`S-V07-HAPPY-LIST-DATES`).
- The service worker (if any) never caches `api.mapbox.com` or `*.tiles.mapbox.com` (Mapbox Product Terms).

- Photos: clustered camera icons rotated by bearing, view cones from zoom 17 (`conePolygon` from `@hcm/shared`; a photo without a bearing gets no cone), bottom sheet on compact and side sheet from medium, lightbox, "photos near this year" (`isPhotoNearYear` and `PHOTO_YEAR_WINDOW` of `@hcm/shared`, one rule for the map and the chip), the rights holder under the licence (V07, V08).

A hash id must match `^[A-Za-z0-9_-]{1,40}$` and is looked up in a `Map`, never put into a selector. The hash is shared with the visitor: the debounced writer remembers the hash it last wrote or adopted and never overwrites one the address gained since, and a `hashchange` wins (`docs/LESSONS.md` #16).
- The city page (`scripts/site/src/page.ts`) is one `main` landmark with a visually hidden level-one heading (the site's title, `hcm-visually-hidden` of `packages/engine/src/engine.css`) around the mount point, so all the viewer draws is inside a landmark (axe's `landmark-one-main`, `page-has-heading-one`, `region`; `docs/ENGINE_API.md` → *The three files of a city*).

## Rules
