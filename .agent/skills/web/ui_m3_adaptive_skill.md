# UI: Material 3 Adaptive Skill

The component kit `@hcm/ui` (`packages/ui`), shared by the engine and the admin: Lit 3 custom elements, Material 3 with M3 Expressive, adaptive to every window size. Since M1 it holds the kit's 19 elements (`packages/ui/src/components/`, all registered by `defineUiKit()`), the theme (`packages/ui/src/theme/`: dynamic colour, `applyTheme`, the system tokens, `BASELINE_THEME`), the window-class layout (`packages/ui/src/layout/window-class.ts`), the self-hosted fonts (`packages/ui/src/fonts/`, `packages/ui/fonts/`) and, under the ownership override, the viewer's elements (`packages/ui/src/viewer/`) and, since M2b, the admin's (`packages/ui/src/admin/`: shell, auth panels, Setup cards). The package guide is `packages/ui/README.md` (elements, theme, fonts, layout, *Decisions*); the component contract is `docs/research/M1-interfaces.md` §5 with change request CR-12.

## Lit without decorators

Decorators are banned by ESLint (their helpers show up as uncovered branches, and Vite 8's transform support is unclear). The pattern, as in `hcm-chip`:

```ts
export const HCM_EXAMPLE_TAG = 'hcm-example';

export class HcmExample extends LitElement {
    static override readonly properties = { label: { type: String } };

    static override readonly styles = css`
        :host {
            display: block;
        }
    `;

    declare label: string;

    constructor() {
        super();
        this.label = '';
    }

    override render(): TemplateResult {
        return html`<span>${this.label}</span>`;
    }
}

/** Registers the element once; calling it again is a no-op. */
export function defineHcmExample(registry: CustomElementRegistry = customElements): void {
    if (registry.get(HCM_EXAMPLE_TAG) === undefined) {
        registry.define(HCM_EXAMPLE_TAG, HcmExample);
    }
}
```

- `static override readonly properties`, `declare` fields, defaults in the constructor (`useDefineForClassFields: true`).
- An idempotent `define…()` function taking the registry (tests pass their own); the element prefix is always `hcm-`; add the tag to `HTMLElementTagNameMap`.
- Styles in a `static override readonly styles` built with Lit's `css` tag (linted by stylelint through `postcss-lit`); colours only from tokens.

## Material 3

- Every element is written in Lit with Google's M3 token values. `@m3e/web` 2.10.0 and `@material/web` 2.5.0 were checked in M1 and not adopted: the contract needs what neither documents (`aria-valuetext` and PageUp/PageDown on the slider, one input event per frame while dragging, sheet heights) and the embed's gzip budget argued against them (`packages/ui/README.md` → *Decisions*).
- **Colour**: `@material/material-color-utilities@0.4.0` (SpecVersion 2025, TonalSpot) generates the light, dark and high-contrast `--md-sys-color-*` tokens (53 per scheme) from the city's seed colour: `themeFromSeed` in `packages/ui/src/theme/dynamic-color.ts`, imported as `@hcm/ui/dynamic-color` (a separate entry point, so the main entry and every node test of the engine and admin never load the colour library) (also `contrastRatio`, `contrastIssues`; an invalid seed falls back to `DEFAULT_SEED_COLOR`). The tokens are precomputed into the manifest (the admin, or `node packages/ui/scripts/gen-theme.mjs --seed '#8B5E3C'`), so the viewer never ships the colour library. The viewer's styles name the tokens without fallbacks; it applies `VIEWER_BASELINE` (`packages/ui/src/viewer/viewer-baseline.ts`: `BASELINE_THEME` cut to the 27 colour tokens the viewer, the kit and the map name, 710 bytes gzip less) before the manifest and under the city's theme (`withViewerBaseline`: a manifest's token map may hold 1 to 200 names, and a missing `secondary` took every focus ring away). A token newly named in the viewer, the kit or the map joins `viewer-baseline.ts` (`theme-tokens.test.ts` fails until it does); a standalone element test applies `VIEWER_BASELINE` itself. Unit tests require WCAG 4.5 for every text pair in the standard schemes and 7 in the high-contrast ones for a set of hard seeds; axe checks contrast per theme in the tour tier.
- **Follow my device is the default** (the owner, 2026-11-13; DECISIONS-for-review.md §222): in the viewer and the admin alike, the theme's mode is `system` (labelled **Follow my device** / **Ca dispozitivul**: `prefers-color-scheme`, `prefers-contrast: more` to the high-contrast scheme, `prefers-reduced-motion` to instant spatial springs, the rem type scale for the browser's text size, forced colours left to the system) and the colours are **Device accent** (`accent`: `device`, the default; `map`, the city's own). `packages/ui/src/theme/device-accent.ts` reads the accent (`readDeviceAccent`: the page's `--hcm-device-accent`, else CSS `AccentColor` only where it is the device's own: Firefox, or Chromium in an installed app; Chrome 150 gives a tab and Safari gives every page a constant, which would paint every city one blue; Android's dynamic colour does not reach the web) and turns the city's four schemes to its OKLCH hue with each colour's WCAG luminance kept and its chroma raised by the accent's over the primary's, 1 to 3 times (`withAccent`; lesson 714: a muted city otherwise hid a vivid accent; Chrome gives an installed app the accent on Linux too, through the desktop portal; no colour library, every contrast ratio stays the city's, error, shadow and scrim keep theirs; a grey accent keeps the map's colours). **Never a silent fallback** (the owner, 2026-11-14, `docs/LESSONS.md` 711): where Device accent cannot show (`deviceAccentState`: `hidden` in every Chrome, Edge and Safari tab, Android included; `grey`), the viewer's Settings and the admin's account menu say so under the choice (`accent.hidden`, `accent.grey`: why, what shows instead, and the way to get it). Both are installable apps since 2026-11-14 (DECISIONS-for-review.md §226, `docs/ENGINE_API.md` → *Installable app*): where the browser offers the install on a computer (`installGivesAccent`, `packages/ui/src/app-install.ts`), the note says installing brings the device's colour and carries **Install app** (`accent.installFix`); Settings and the account menu show **App** with **Install app** only while `beforeinstallprompt` waits. The app's service worker goes to the network first and never keeps data or another origin (lesson 707). The viewer stores the choice per city (`hcm:<cityId>:accent`, `setAccent`), the admin per browser (`hcm:admin:accent`, the account menu's **Colours**); Settings' live seed preview shows the seed's own colours. A user who chose Light or Dark before keeps it (the stored `theme`). Tests: `packages/ui/test/theme/device-accent.test.ts`, `e2e/specs/viewer/device-accent.spec.ts`, `e2e/admin/specs/shell/accent.spec.ts` (Chromium tabs: the accent is emulated with `--hcm-device-accent`).
- The library's ESM files import without file extensions: fine for Vite and Vitest, but plain Node needs the resolve hook the CLI scripts register (`scripts/seed/migrate-legacy.mjs`).
- **Shape and motion**: the M3 shape scale, spring-derived motion curves; `prefers-reduced-motion` disables fly animations.
- **Fonts**: self-hosted Roboto Flex (`latin`, `latin-ext`, weight axis) and a Material Symbols Rounded subset holding only the names of `ICONS` (`packages/ui/src/icons-sorted.ts`, sorted from the lists of `packages/ui/src/icons.ts`: the kit's, the viewer's and every `POI_ICONS` name); never Google Fonts (GDPR). The families are namespaced (`HCM Roboto Flex`, `HCM Material Symbols Rounded`: `TEXT_FONT_FAMILY`, `ICON_FONT_FAMILY`) and registered through `document.fonts` by `installFonts(document, baseUrl)`, the kit's only global side effect (an `@font-face` inside a shadow root is ignored, an injected stylesheet would break the CSP). An icon used anywhere is first added to `UI_ICONS`, then `npm run fonts:build --workspace @hcm/ui` rebuilds the subset; the static gate `fonts` (`fonts:check`) fails when the committed files differ or a name does not shape to one glyph. The engine build copies `packages/ui/fonts/` to `dist/fonts/`.
- **Inline styles only through the CSSOM**: never Lit's `styleMap` (ESLint refuses its import) or a `style=${…}` binding (the e2e console guard catches it). Their first render writes a `style` attribute, which the city page's CSP (`style-src` without `'unsafe-inline'`) refuses, so a kit slider or progress bar logged a CSP violation in the viewer smoke. Use the element directive `cssProperties({...})` (`packages/ui/src/components/css-properties.ts`), which sets and removes custom properties with `style.setProperty`. Lit's own styles use adopted stylesheets, which the CSP allows.
- **Charts without a chart library** (the Statistics view, the owner's "prettify" of 2026-11-13): stat cards for key numbers, horizontal bar lists, step bars and the per-day sparkline are plain elements and one inline SVG (`packages/ui/src/admin/crashes/statistics-bars.ts`, `statistics-funnels.ts`, `statistics-format.ts`). A bar's width is a custom property through `cssProperties`; the bar is `aria-hidden` and the list's own text (name, number, share) is its text alternative. Long lists show five rows and fold the rest in a native `<details>` (**Show all**); a page's own `.statistics` prefix scopes its rules inside a shared shadow root.
- **Stacking**: the viewer sets `--hcm-sheet-z-index` so the kit's modal sheets cover its floating controls; the open FAB menu sits above the consent banner and the snackbar. The modal sheets and the lightbox are positioned against the viewer's modal layer (z-index 30, the whole viewer), which draws above Mapbox's logo and attribution; those move into the part of the map an open modal sheet leaves in view (`legal-lift.ts`), and nothing needs them where the lightbox or a full-screen dialog hides the map; About uses the native `<dialog>` (top layer) and carries no copy of them (the Pixel 9 Pro review, P3). On a landscape phone (compact height) the open FAB menu lays its items in rows that stack upwards across the map's width, 48 px tall, with the lying card, the chip and the zoom group stepping aside; a window too short even for that scrolls the menu (P1; `dock-styles.ts`, `fab-menu.ts`'s `--hcm-fab-menu-flow`). A chosen light or dark theme is `color-scheme: only light|dark`: Chrome's dark theme for sites (Android, dark system) repaints any element whose used scheme is light, which no computed style shows (P2; `theme/apply.ts`). A modal surface over another makes the one beneath inert: under the lightbox the viewer's modal sheets are `inert` (the tour found the photo sheet's image, handle and Close usable beneath it).
- **Floating controls stack with M3's 8 px**: the viewer's strip at the map's foot (`--hcm-map-chrome`, 42 px: Mapbox's collapsed attribution, 24 px at 10 px from the edge, plus 8), then the timeline (`--hcm-timeline-block`, 84 px, which `hcm-timeline` holds whatever the page's font: no `ol` margin), the FAB (`--hcm-fab-size`), each `--hcm-dock-gap` apart. **The timeline's orientation** (the owner, 2026-11-08): a compact height (landscape phones, `data-compact-height`) lays it at the foot of the map; otherwise a compact width (< 600 px: phones held upright, narrow windows) stands it on the leading edge, 68 px wide, from the top gutter down to the chip's row; everything else lays it down across the map's whole foot, from the leading gutter to `gutter + 72px` from the trailing edge (the menu button's and zoom group's column; the owner, 2026-11-14: no narrower centred bar; `S-V04-HAPPY-TIMELINE-FULL-WIDTH` measures it at 768, 1440 and 2560, `S-V04-HAPPY-TIMELINE-FULL-HEIGHT` the standing card's height at 360 × 800). `layoutFor` decides, the frame carries it as `data-timeline="horizontal|vertical"` and every orientation rule keys off that attribute, never off a width query. The "photos near this year" chip belongs to the timeline card: standing, 8 px under its foot on its leading edge, a row above the FAB, which keeps the bottom trailing corner, and the open menu's items begin above the chip's row (`.dock.chip ~ .dock.menu` sets `--hcm-fab-menu-gap`: the owner's phone had *Despre* over the chip's end); lying, 8 px above the card on its leading edge (`var(--hcm-gutter)`, the card's start; the owner saw it once 72 px from the map's edge, aligned to nothing), and on its trailing edge on a short window, whose menu opens on the leading side: there the card takes the trailing column instead (`inset-inline: calc(var(--hcm-gutter) + 72px) var(--hcm-gutter)`, the chip ending at the trailing gutter) and the menu's items end above the chip's row whether or not a chip shows (lesson 504). **More years than the card holds scroll**: the track is at least 30 px per gap (`--hcm-gaps`), the card scrolls with no bar and the selected stop snaps into view except while dragging (lesson 505); test a timeline with more stops than the fixture's. Standing, the top docks (toast, consent), compare's bar and the focused skip link begin after the card (`--hcm-top-start`); compare's handle sits above the map's middle, clear of the lying card and its chip. The vertical card is 68 px because at 320 px the open menu's widest item (210 px in English) begins 94 px from the edge and must stay 8 px from the timeline (the tour's gap check). **The selected year's pill never hides another year's label**: lying, the labels are a row below the pill (20 px under the ticks, below the pill's 44 px); standing, the years are the ruler in the pill's lane, masked from the rail by the card's colour, and the phone's height spaces them wider than the pill (`kit-timeline-layout.test.ts` measures every label at every selected year). A dock or popup is a box around what it draws: the menu's and toast's docks and `hcm-fab-menu`'s host take no pointer, only the FAB, the items and the snackbar's surface do (`docs/LESSONS.md` #57, #58). Where the FAB sits beside the taller timeline (medium and up), the open menu's items end `--hcm-fab-menu-gap` (8 px above the timeline, not above the FAB): wider than the FAB, its last item lay on the timeline's thumb at 768 px (the visual audit; the open menu may cover only the map's content and the two top docks).
- **Focus rings on coloured surfaces**: `focusRing` (and the viewer's own `:focus-visible`, and the admin's `adminBase` since CR-M2c-29) draws `--hcm-focus-ring-color`, secondary by default; a surface close to secondary sets it for everything on it (the snackbar: inverse primary; the error card: on-error-container). Mapbox's attribution is white in every theme, so the viewer gives it `light-dark()` of primary and inverse primary (`docs/LESSONS.md` #60). A ring is drawn where nothing clips it: a control that fills or touches the edge of a box that hides its overflow draws its ring inside (the map canvas `outline-offset: -3px`, the sheet's drag handle a round ring inside its 48 px box), and Mapbox's full attribution gets the 3 px its links' offset-free rings need (`docs/LESSONS.md` #68).
- **No `header` inside a component**: a dialog's, sheet's or lightbox's title row is a `div.header`; a `header` outside sectioning content is a page banner, and axe found a second banner under the lightbox and one inside the admin's top bar. A dialog's name comes from its headline (`aria-labelledby`) or `aria-label`; a `nav` always has a name (the lightbox's `lightbox.navigation`).
- **Never lay out on `:host` what a page can undo**: a page's style on the element (`hcm-map-viewer { display: block }`) beats the component's `:host` rule, so a grid or flex layout lives on an inner wrapper (the viewer's `.viewer`); `:host` keeps only what may be overridden (`docs/LESSONS.md` #23).
- **The kit's snackbar positions itself** at the bottom of its positioned container (`:host { position: absolute; bottom: 16px }`): an app that docks it elsewhere sets `position: static` on it from outside (the viewer's top toast dock), or it lands off screen.
- **Text on a fixed backdrop**: the lightbox scrim is dark in every theme, so no theme colour is drawn on it directly: its header and error message sit on `surface-container` with `on-surface` text, its arrows are tonal icon buttons. Colours stay tokens (stylelint forbids hex and named colours). A component that must be dark in the dark theme (a chip, a pill, a badge) takes a surface or a container role, never `inverse-*`, `primary` or `error` as its fill: M3 makes those light in the dark theme, and every contrast check still passes (the timeline's chips on the owner's dark Android, `docs/LESSONS.md` 694); its test reads the fill's lightness per scheme (`e2e/support/chip-colours.ts`). The scrim is opaque (a translucent one let the photo sheet and the menu show around the photo), and the stage's single track is `minmax(0, 1fr)`: an image's percentage `max-block-size` inside an `auto` grid track resolves against its own height, so a landscape photo on a short window was cropped instead of fitted.

## Adaptive layout

- Window classes are measured on the **host element** with container queries and a `ResizeObserver` (which also calls `map.resize()`), not on the viewport: compact below 600, medium 600–839, expanded 840–1199, large 1200–1599, extra-large from 1600 (`'extra-large'`); compact height below 480 for landscape phones (`WINDOW_CLASS_BREAKPOINTS`, `windowClassFor`, `isCompactHeight`, `WindowClassController`). The public viewer also docks its sheets in a medium window from 760 px wide that is not short (`DOCKED_PANE_MIN_PX`, `isDockable`, `ViewerState.dockable`: the Pixel Tablet upright, `DECISIONS-for-review.md` §169c). A control that moves along one axis inside a scrolling panel leaves the other axis to the browser (`touch-action: pan-y` on `hcm-slider`, which waits 8 px for a finger's direction; §169b); the timeline names every year exactly 40 px apart (`YEAR_GAP_PX`) at every size and both ways from the card's leading edge, never stretched to the card nor spread by date, lying with a dot per year on the rail (the selected one's bigger), labels 13 px lying and 14 px standing or compact, a label that would touch its neighbour's left out (`crowdedLabels`); where they do not fit it scrolls, each edge with years beyond fading under a 48 px button that pages that way and names the furthest year, and it opens centred on the selected year, also when the card had no size or was a pill when the year was set (`timeline-edges.ts`, `timeline-scroll.ts`; §169a; the owner, 2026-11-14: "too crowded", "way nuked", then the smaller gap, dots and the scroll hint).
- An image's CSS size is not its decoded size: a picture from an outside source (USGS's browse copies reach 37,440 x 1,920 px) goes through `PicturePort`'s `thumbnail` or `preview` (`packages/admin/src/imagery/pictures.ts`), never straight into an `<img>` (`docs/LESSONS.md` 387).
- Touch targets at least 48 dp (`TOUCH_TARGET_MIN_PX`), safe areas, `dvh`, logical properties (the viewer runs right to left in Arabic: `inset-inline-*`, `margin-inline-*`, `text-align: start | end`, never `left` / `right`; a control whose keys or pointer maths are physical reads `logicalKey(key, element)` or `:dir(rtl)`, as the slider, the segmented button, the toolbar, the lightbox and the timeline do; `hcm-icon` mirrors `chevron_*` and `arrow_*` right to left by itself). A control drawn smaller (the slider's 4 px handle, the timeline's 40 px thumb, the 40 px icon button and button, the 32 px chip) gets the `touch-target` class and the kit's `touchTarget` styles (a centred 48 × 48 `::after`), and nothing may hide its overflow: `touchTarget` sets `overflow: visible` above the state layer's `.interactive { overflow: hidden }`, which had cut every kit button's ring to its own box (LA-6; `packages/ui/test/components/touch-target.test.ts` hit-tests the ring, as the tour's `targetSizeOf` does); a link of a list is 48 px tall (`detailStyles`); a link inside a sentence is exempt (WCAG 2.5.8).
- **Text buttons over the map only where a mouse points** (the owner, 2026-11-13): a wide label ("Fotografii din jurul anului …") is an icon button named in full, its tooltip the same text, on phones and tablets; the text chip shows only on an expanded or wider window that is not short and not under a finger (`(pointer: coarse)`; `viewer-near-year.ts`).
- Rings never cover rings (LESSONS 69, 70): 40 px buttons in a row keep 8 px apart and 32 px chips' wrapped rows 16 px (`row-gap: 16px`), a short link gets `min-inline-size: 48px`, a check box is M3's (an 18 px box with a 2 px `on-surface-variant` border, `appearance: none`, the class `touch-target`; a native one reaches 1:1), and a file chooser is a `hidden` input opened by a kit button (a visually hidden input inside a label fails non-text contrast and focus obscured). `hcm-toolbar`'s roving `tabindex` sits on its slotted hosts, which hides their shadow buttons from Tab: the tour's Tab round reports them as never reached, so a tool row the user must Tab through is a named `role="group"` of separate stops (the places editor's drawing tools).
- Floating controls carry `data-layout-check="<name>"` (the viewer's timeline, note, chip, menu, consent banner and toast), but the tour no longer depends on the marks: its generic checker finds the kit's floating components itself (`hcm-fab-menu`'s FAB and menu, `hcm-timeline`, `hcm-toolbar`, `hcm-chip`, `hcm-snackbar`, `hcm-consent-banner`, `hcm-sheet`, the admin's navigation and top bar, Mapbox's controls) and checks that no two overlap, that floating touch targets keep 8 px apart on compact and medium, and that every control is on top where it is drawn (`docs/TESTING.md` → *The tour's checkers*). A popup's host must not stay a hit target where nothing of it is drawn: the open FAB menu may cover what is beneath its items, not more. On a phone held upright the "photos near this year" chip sits 8 px under the standing timeline's foot, a row above the menu button (from 600 px on the lying card's leading edge 8 px above it, on a landscape phone on its trailing edge); on a landscape phone the FAB menu is at most `--hcm-fab-menu-max-block-size` tall and its items continue in a second column (a scrolling menu would not be keyboard-reachable). The menu docks on the leading edge there and sets `--hcm-fab-menu-align: flex-start`, so the FAB and its items line up on that edge: aligned to the end, the wider wrapped menu moved the FAB from under the finger. A control must never move when it is tapped (the tour cannot see this: check the screenshots).

- Romanian labels are long: a control's width comes from its content and its container, never an equal share. `hcm-segmented-button` segments are content-sized (`flex: 1 1 auto`), never wider than their container, and a long label wraps inside a taller segment instead of scrolling the page sideways; at compact width the Settings dialog drops the theme icons (only the check mark stays). Single words that still do not fit stack one segment per row (`stacked`, decided on the next frame after a resize); only new labels measure them side by side again, so a parent that builds its options in `render` (a new array with the same segments on every update) never flashes the row past the dialog's edge (`docs/LESSONS.md` 295). An element that re-measures on a property change compares what the property draws, not its identity.
- A container query or media query that narrows a component comes after the base rule it overrides: at the same specificity the later rule wins, so a narrow rule written first is dead code that looks applied (the georeferencer's residual table kept its 8 px cell padding on phones until six far pairs scrolled it sideways, `docs/LESSONS.md` 181). A table lets its cells wrap (`nowrap` cells cannot shrink, and a reader's text spacing widens every one); measure it with the longest data it can hold and under the checker's text-spacing sheet (`packages/ui/test/admin/georef/residual-fit.test.ts`).
- Mapbox's attribution is white in every scheme and colours only its links: a map that shows a layer's plain-text credit gives `.mapboxgl-ctrl-attrib-inner` the links' colour (`rgb(0 0 0 / 75%)`), or the dark scheme's light text reads white on white (`docs/LESSONS.md` 182, `packages/ui/src/admin/map/hcm-admin-map.ts`).
- A sibling margin of a shared style (`detailStyles`' `.details li + li`) must not reach a list laid out by a grid or flex `gap`: the margin adds to the gap and pushes every later item down (the POI sheet's second photo thumbnail sat 4 px lower; `docs/LESSONS.md` #22). Reset it in the component and measure the items' edges in a unit test.
- Navigation: bottom sheet and navigation bar on compact, side sheet and rail from medium; no drawer.
- A bottom sheet's drag handle is a 48 × 48 button at the sheet's top edge with the 32 × 4 bar in its middle (M3): a smaller handle's ring rose past the sheet, which hides its overflow, and was cut to 36 px. A segment of `hcm-segmented-button` is at least 48 px wide, so its ring never sticks out of a narrow container (a ring that reaches past a box is scrollable overflow once nothing hides it).
- A docked sheet fills its pane and its body scrolls: every box between the pane and the sheet passes a definite height (the photo list's wrapper is `display: contents`); one auto-height wrapper let the list grow past the pane's hidden overflow (`docs/LESSONS.md` #59). An `hcm-sheet` hides its empty `actions` row.
- A title that may not fit wraps (`overflow-wrap: anywhere`); an ellipsis is a cut label to the tour, and WCAG 1.4.12's text spacing found the lightbox's on a 320 px phone.
- The admin (`packages/ui/src/admin/`, entry `@hcm/ui/admin`, M2b): a navigation bar on compact windows, a collapsed rail from medium, the expanded rail (labels beside the icons, not modal) from large, and on a landscape phone (compact height) a rail with the account button at its foot and no top bar. A card re-created by a layout change keeps nothing of its own: typed fields live in the controller's state.

## Accessibility

- A toggle `hcm-button` sets `.pressed` (true or false), which its inner `<button>` states as `aria-pressed`; ARIA on the host names nothing (the focus is delegated to the inner button). Undefined is no toggle.
- A text button inside an error-container `.alert` reads in `on-error-container` (`editingStyles`); icon buttons on the bulk bar in `on-secondary-container` (an overflow menu's button through its exported part `more-button`): the defaults fail 3:1 or 4.5:1 in high contrast.
- A lazy area chunk defines every element it renders (`<hcm-admin-map>` in the settings chunk: lesson 136); `packages/ui/test/admin/editing/areas.test.ts` checks the map-showing chunks.
- Every interactive element has a role and an accessible name; keyboard order follows the visual order; focus returns to the opener when a dialog or lightbox closes.
- Move the focus before announcing an action: a menu closes and focuses its button, then fires `hcm-select`, because whoever reacts records the focused element as the opener (a vanished menu item left the focus on `<body>`; `docs/LESSONS.md` #12).
- Never disable or remove the control that has the focus without moving the focus first: Chromium drops it to `<body>`, where Esc and the arrow keys no longer reach the dialog (the lightbox's Next button on the last photo; `docs/LESSONS.md` #19).
- `hcm-dialog` keeps 4 px between its scrolling content and its actions, so an action's 48 px touch target never covers the control the content shows at its edge (CR-M2c-29).
- **The editors' number fields** (`packages/ui/src/admin/editing/number-fields.ts`): bind `.value` with `numberValue(text)` (it leaves the admin's own spelling of the same number, and an unfinished one, under the cursor), commit on `input`, and show the problem only for fields in `LeftFields` (left once since the item opened, `@focusout`).
- Every modal (native `hcm-dialog`, a modal `hcm-sheet`, the lightbox) traps Tab with `trapTab`; Shift+Tab on the focused container itself wraps to the last control, so a modal that focuses its container on open is never left backwards.
- A live region exists, empty, before the text it announces: one created together with its text is not announced. `hcm-snackbar` keeps a visually hidden polite region and fills it with the message alone `ANNOUNCE_DELAY_MS` after it shows (`docs/LESSONS.md` #20); the overlay list's region is always rendered.
- Forced colours stay readable; nothing is conveyed by colour alone.
- Tests: Vitest browser mode with `page.getByRole`, keyboard interaction, RO and EN strings, window-class variants, reduced motion (`quality/testing_strategy_skill.md`).
