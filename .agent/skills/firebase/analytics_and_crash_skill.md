# Analytics and Crash Reporting Skill

"Full Firebase support for crashes and analytics" (user request, `docs/research/PLAN.md` → *Addendum 2*), within the privacy and cost rules. Architecture summary: `docs/ARCHITECTURE.md` → *Analytics and crashes*.

## Analytics (GA4 for Firebase; Performance Monitoring in the admin only)

- GA4 in both the public viewer and the admin, through the analytics module of the Firebase JS SDK (`firebase` package). Performance Monitoring is not part of the public viewer (below); the admin, whose addresses hold no visitor position, may add it.
- **Loaded only after consent**: an M3 consent banner (RO/EN); Consent Mode v2 defaults denied; `analytics_storage` granted on accept. The decision is stored and can be withdrawn in About. The banner's text (`consent.body`) is at its length limit: at 915 × 412 with WCAG text spacing a longer one covers the map's centre and fails the tour's occlusion check (2026-10-31, §76: "usage and performance" fitted only by saying "Otherwise, no cookies" in fewer words); run the `consent banner` tour journey at `tour-c915l-light-{ro,en}` after changing it.
- The viewer still never reads Firestore: the Firebase app and analytics are lazy-loaded only when the manifest has a `measurementId` **and** the visitor consented. Code: `packages/engine/src/telemetry/` (`consent.ts`: the choice per city under `hcm:<cityId>:consent`, Consent Mode v2 starting denied; `analytics.ts`; `cookies.ts`; `errors.ts`; `telemetry.ts`; `firebase-sdk.ts`, the one lazy chunk with the Firebase app and analytics modules).
- Firebase Analytics refuses to start without the web app's `apiKey`, `appId` and `projectId`; until the manifest carries them (`city.analytics.firebase`, change request CR-9) the engine logs `analytics off` and sends nothing, so the consent banner shows but no GA request follows.
- **The viewer's Firebase app is always the named app `hcm-viewer`**, so an embedding page keeps its default app for its own Firebase (the default app was needed only by Performance Monitoring, `docs/LESSONS.md` #9).
- **Never the hash** (`docs/LESSONS.md` #24, `docs/research/DECISIONS-for-review.md` §18a): GA4 gets `page_location` (origin and path) and `page_path` on its configuration and `page_location` on every event, `send_page_view: false`, and `allow_google_signals` and `allow_ad_personalization_signals` false. Performance Monitoring sends `location.href` up to the first `?` (the whole hash: the map view, after *My location* the visitor's position) and has no setting against it, so it stays out of the public viewer. The GA4 web stream's enhanced measurement of history changes must be off (the viewer rewrites its hash with `history.replaceState` on every move): the provisioner's job (CR-M2-37 in `docs/research/M2-interfaces.md`).
- **Withdrawal expires the cookies** (`docs/LESSONS.md` #25, §18c): a change from granted to denied, with analytics configured, expires every `_ga` and `_ga_*` cookie host-only, for each parent domain and for every path prefix of the page (`cookies.ts`), at once and again after the SDK applied the denial; GA4 starts with the consent as it is when the chunk arrives. A first *Decline* touches no cookie: an embedding page may run its own GA4.
- The ES module build loads the SDK as its own chunk only after consent; the IIFE build inlines it (Rolldown has no code splitting for IIFE), about 24 KB gzip downloaded but not run before consent (CR-10, `docs/research/DECISIONS-for-review.md` §13a). The city pages load `engine.mjs`.
- Events: `page_view`, `layer_toggle`, `year_change`, `photo_open`, `poi_open` (PLAN Addendum 3), `share` (the store's `logShare()` after a completed share or copy, never a cancelled one), `compare_open`; admin flow events for setup steps and imports. Opacity slider moves are not events (too chatty, no product question behind them). **No PII**: no email, no free text, no precise visitor location.

## Field measurements (`docs/ARCHITECTURE.md` → *Field measurements*, `docs/research/DECISIONS-for-review.md` §76)

- **What**: the Core Web Vitals (`web_vitals`, Google's `web-vitals` 6.2.3, attribution build) in both apps; the viewer's boot (`viewer_timing`), `manifest_error`, `map_unavailable`, `map_errors` (counted by kind, the first at once, then at most every 30 s and at page hide), `photo_timing`, `compare_timing`; the admin's `admin_ready`, `setup_check`, `provision_item`, `install_build`, `editor_save`, `job_done`. Every one carries `app`, `window_class`, `release`.
- **Where**: `web-vitals` only in the lazy field chunks (`packages/engine/src/telemetry/field-sdk.ts`, `packages/admin/src/firebase/field-sdk.ts`; the dependency-cruiser rule `web-vitals-only-in-the-consented-chunks`), loaded with the Firebase SDK after consent. The viewer's boot and store call `telemetry.measure?.(…)` (`FieldRecorder`, `packages/engine/src/telemetry/field.ts`, `performance.mark`/`measure` as `hcm:<phase>`); the admin reads its state (`FieldWatch`) and wraps the editors' Firestore (`measuredStore`, `packages/admin/src/app/field.ts`), so no feature changes to be measured. Measurements before consent wait in memory (at most 30) and leave only after a grant.
- **The guard**: every event of both apps, old and new, is checked by `createViewerGuard` / `createAdminGuard` of `@hcm/shared` (`packages/shared/src/telemetry/`) before `logEvent`: the app's own strict zod table, GA4's limits (name 40, 25 parameters, values 100), no `?`, `#`, `@`, coordinate (four decimals or more) or tile path (`/z/x/y`) in a text value, a page budget (300, 100 per name, fewer for the noisy ones). A new event joins its app's table, a row of the ARCHITECTURE table, and a unit test; a new parameter that is text is a short token, never free text or a URL.
- **Bundles**: the field chunk has its own budget row (`field-sdk`, 9 KB) in both apps; the engine's IIFE inlined it (§76e) until its extras (§186): now `extra-field-sdk` (7 KB, the event guard taken from the IIFE) and `extra-firebase-sdk` (16 KB) have their own rows.
- The `measurementId` is detected by the Setup Assistant card "Analytics and crash reporting" (`setup.analyticsConfig`: Firebase Management `webApps/{id}/config`, `fn-admin@` needs `roles/firebase.viewer`) and written with the web app's public ids to the city doc and the manifest; the admin accepts the GA terms on Google's page.
- **Reports** (§76f, the user's decision of 2026-11-01): Setup step (g)'s **Create the measurement reports** registers the parameters GA4 needs as event-scoped custom definitions on the property whose web stream sends the measurement id (`packages/admin/src/google/analytics-reports.ts`, a lazy chunk; Analytics Admin `v1beta` with the owner's `analytics.edit` consent; idempotent). Its lists `FIELD_DIMENSIONS` and `FIELD_METRICS` follow the guard's schemas (a unit test fails on a parameter no event sends): a new parameter worth a report joins both lists and `docs/ADMIN_GUIDE.*.md`.

## Crashes (web equivalent of Crashlytics)

- Global `error` and `unhandledrejection` handlers plus Lit and engine error boundaries.
- After consent: GA4 `exception` events with the fatal flag.
- The reporter never throws, redacts like `createLogger` plus URL queries (a tile URL carries the Mapbox token), sends at most 5 reports per page and one per message per 10 s.
- Always (no PII, rate-limited): `telemetry.reportError`, a public HTTPS function that writes a redacted stack, release, viewport and window class as a structured log with `@type: type.googleapis.com/google.devtools.clouderrorreporting.v1beta1.ReportedErrorEvent`, so **Cloud Error Reporting** groups crashes, alerts on first sight and emails. Its contract (`docs/research/M2-interfaces.md` §3.4; schemas in `packages/shared/src/api/telemetry.ts`): the `Origin` must be a viewer or admin origin (403 otherwise, and the origin decides the service, `viewer` or `admin`), the body at most 16 KiB (413), at most 10 reports per client and 15 per instance per minute (429, counted in memory, never in Firestore; `ERROR_REPORT_LIMITS`), JSON sent as `text/plain` so the browser sends no preflight, validated with `errorReportSchema` (the engine's `ErrorReportPayload`), redacted again with `redactText` of `@hcm/shared`, and `context.reportLocation` always set so Error Reporting also groups Firefox and Safari stacks. The manifest builder puts its URL into every manifest as `analytics.errorEndpoint`, so crash reports work before analytics is set up.
- How the endpoint behaves (`functions/src/telemetry/`, CR-M2-12): a preflight (`OPTIONS`) from an unknown site gets 405, any method but `POST` 405, a foreign `Origin` 403 without CORS headers; every refusal after the origin check carries `Access-Control-Allow-Origin`, so the page can read the status. The per-client key is a salted hash of the last `X-Forwarded-For` hop, held in memory for the current minute only; with `maxInstances: 2` at most 2 × 15 reports a minute reach the logs project-wide, and each logged entry is cut to `REPORTED_EVENT_MAX_BYTES` (16 KiB; the message is shortened, the stack and context kept): the worst case is about 30 × 17 KiB a minute, about 22 GiB in a 31-day month, under Cloud Logging's 50 GiB free tier (`DECISIONS-for-review.md` §42f). Cloud Run's own request log (one short entry per request, also for refused ones) is not capped by the handler: excluding it is a sink exclusion, a cloud change that stays *Ask first*; App Check enforcement (`HCM_APP_CHECK=enforce`) is likewise a later, ask-first step. A stack frame's location is parsed **before** redaction (`redactText` drops a frame's `:line:col` together with its URL's query), Firefox and Safari stacks get the error message in front, and the accepted report becomes one structured ERROR entry (`write` of `firebase-functions/logger`), no Firestore write. It runs as `fn-crash@`, an account with no project role (a log entry needs none), so the one public endpoint can reach neither Firestore nor Storage.
- Source maps are uploaded as release artifacts for de-minification.
- Functions and the Cloud Run pipeline report through structured error logs.
- The Setup Assistant's "Crash reports" panel lists the latest Error Reporting groups through the admin callable `telemetry.listGroups` (Error Reporting `groupStats` over REST; `fn-admin@` needs `roles/errorreporting.viewer`): a 403 that names the disabled API answers `apiError.cloud.apiDisabled` with `{api}`, any other 403 `apiError.cloud.permission` with the role, anything else `apiError.errorReporting.unavailable`; every message is redacted again before it leaves.

- **The admin** (M2b, `packages/admin/src/app/telemetry.ts`, `packages/admin/src/app/errors.ts`, `packages/admin/src/firebase/analytics.ts`): GA4 on its own default Firebase app, loaded only after the admin's own consent (stored as `hcm:admin:consent`; withdrawing it expires the `_ga` cookies), page views of the hash route and Setup events without PII; crash reports go to `telemetry.reportError` as the `admin` service only once the server answers (normal mode), from global hooks and the elements' error boundaries. The reporter mirrors the engine's (CR-M2b-30 proposes moving the shared part into `@hcm/shared`).
- **The Setup Assistant's analytics card** (step g): `setup.analyticsConfig` when it opens and every 15 s for 15 minutes after the owner follows the Firebase console link; the GA4 stream setting (`analytics.edit`, Analytics Admin `enhancedMeasurementSettings.pageChangesEnabled` off and read back, CR-M2-37); the crash e-mail switch toggles the `crash-alerts` alert policy (`cloud-platform`); the crash panel and the `#/crashes` page list `telemetry.listGroups`.

## Tests

- Consent gating (`e2e/specs/viewer/consent.spec.ts`, V19): no GA or Firebase request before an answer or after "Decline" (the firewall and the mock APIs' record); "Accept" runs the **real** Firebase SDK against the mock APIs: the Firebase web config, Installations and a stand-in gtag.js (`e2e/mock-apis/gtag.ts`) that turns each logged event into a recorded `POST region1.google-analytics.com/g/collect?en=<event>&ep.<param>=…&dl=<page>` while `analytics_storage` is granted and the property is not disabled; withdrawing in About stops them. The manifest of these specs carries generated Firebase app ids (`E2E_FIREBASE_APP` in `e2e/fixtures/world.ts`, the API key assembled at run time so the source holds no Google-key-shaped string).
- Crash reports (`e2e/specs/viewer/crash-reporting.spec.ts`, V20): an error thrown into the page reaches the e2e telemetry endpoint redacted (no hash, query, token or e-mail), a down endpoint changes nothing visible, an error storm is capped at five reports, one per message.
- Privacy (`consent.spec.ts`): every GA4 hit's `dl` is the origin and path even after *My location* (the stand-in falls back to `location.href` like gtag.js, so a forgotten `page_location` would show), no request reaches the Performance Monitoring hosts (`S-V19-BAD-HASH-NEVER-SENT`); the stand-in writes `_ga` and `_ga_<container>` once consent is granted, and a withdrawal expires them while a first *Decline* leaves a page's own `_ga` (`S-V19-HAPPY-COOKIES-EXPIRED`, `S-V19-BAD-DECLINE-KEEPS-PAGE-COOKIES`).
- Unit tests: event payloads with the hash-free page location, the cookie expiry, a withdrawal during the SDK load, the error reporter's redaction and rate limit (`packages/engine/test/telemetry/`).
- Field measurements (`e2e/specs/viewer/field-measurements.spec.ts`, V19): after Accept the field chunk is fetched and GA4 receives `viewer_timing` and `web_vitals` (TTFB, FCP; LCP after a click; CLS once the page is hidden: `hidePage` of `e2e/support/ga4.ts` overrides `document.visibilityState` and fires a bubbling `visibilitychange`), each validated with the viewer's own schema (`viewerEventProblem`); nothing before an answer, after Decline or after a withdrawal; an exception naming coordinates never reaches GA4; a tile-error storm arrives as two `map_errors` events. Read the console only after leaving a page whose tiles keep failing (`about:blank`), or a late 503 fails the teardown. Unit tests: the guard and the vitals mapping (`packages/shared/test/telemetry/`), the recorder, the loader's hold and flush, the chunk (`packages/engine/test/telemetry/field*.test.ts`), the hooks (`packages/engine/test/core/measure.test.ts`), the admin's watch and measured store (`packages/admin/test/app/field.test.ts`).
- The CSP lists the googletagmanager, google-analytics and firebaseinstallations hosts only for these SDKs (`web/web_security_skill.md`); the Performance Monitoring (`firebaselogging`) hosts left the site CSP with CR-M2-36 (`scripts/site/test/csp.test.ts` keeps them out).
- The endpoint: `functions/test/telemetry/` (`@S-A24-HAPPY`, `@S-A24-BAD-FOREIGN-ORIGIN`, `@S-A24-BAD-RATE-LIMITED`, `@S-A24-BAD-TOO-LARGE`, `@S-A24-BAD-INVALID-BODY`) through `.run()`, with the redaction of a frame pinned by `functions/test/telemetry/error-event.test.ts`.

## Noise, the browser label and the journeys (DECISIONS §199, 2026-11-13)

- An error the page did not cause is never a crash: `crashNoiseOf` (`packages/shared/src/telemetry/crash-noise.ts`) names it `injected` (a browser's own script: `__firefox__`, `__gCrWeb`, a stack that is the page's address at line 1), `extension` or `aborted`; the viewer's and the admin's reporters log the reason and send nothing, and `telemetry.reportError` drops it again for older pages. Add a new kind there, with a test, rather than filtering in Error Reporting.
- The browser of a report is `clientLabel(User-Agent)` (`Firefox 145 mobile`), set by the endpoint as `httpRequest.userAgent`: never log the User-Agent string. The admin's report names its route id (`routeOfHash`), never the record after it.
- Read a crash group's top frames on the Crashes page before deciding: a stack that is all Mapbox may still need a work-around of ours (`packages/ui/src/map/context-restore.ts`).
- A key journey is an event with ids, codes and milliseconds only: the viewer's `story_open`, `locale_change`, `theme_change` beside the earlier ones; the admin's `admin_action` (`packages/admin/src/app/field-actions.ts`, its `MEASURED_ACTIONS`) with the outcome `ok` or the refusal's code. A new event goes into `VIEWER_EVENT_PARAMS` or `ADMIN_EVENT_PARAMS` with its schema, and only after consent.

## Wizard funnels (DECISIONS §200, 2026-11-13)

- One helper for every wizard: `@hcm/shared/funnels` (a subpath; never import it from the engine). A page returns a snapshot of its wizard (`*-funnel.ts` beside the page, a pure function with its own unit test) and calls `trackFunnel` on every render (an area page calls `trackAreaFunnels` in its `updated`); the admin's `FunnelHub` (`packages/admin/src/app/funnels.ts`) listens on the window and sends through `telemetry.measure`, after consent only. A new wizard joins `WIZARD_IDS`, `WIZARD_STEPS` of `statistics-view.ts` and the Statistics strings in ro and en.
- Codes, never words: a step id and an error code are short tokens (the catalogue key or the refusal's code). The guard's `FUNNEL_EVENT_PARAMS` and the hub's token check drop anything else.
- Errors shown: the admin's error notices are `ui_error` (`isErrorNotice` decides by the key), the viewer's `error.…` toasts too; never the message's text.
- Do Not Track and Global Privacy Control are a refusal until the person accepts (`privacySignal`): no banner, nothing stored for it.
- The owner reads the funnels on Crashes → Where people get stuck (§203): **Show the numbers here** asks `analytics.readonly` through the shell's Google consent and reads the Data API `v1beta` `batchRunReports` from the browser (`packages/admin/src/google/analytics-data.ts`); `runFunnelReport` is `v1alpha` only, so the funnel comes from `runReport` rows. Each period is cached in memory for the session, read on a click, never polled (Home's Visitors card reuses `StatisticsSource.latest` and never asks Google itself, §238). A new report dimension is a parameter `FIELD_DIMENSIONS` registers; the Data API fake (`packages/test-support/src/fakes/google-analytics-data.ts`) refuses an unregistered one with 400 like GA4. Admin screen rows drop both `(not set)` and an empty `route` (page views before the screen name was registered; blank first bar, 2026-11-20).
- Every event carries `app_surface` (`SURFACE_PARAMS`: `viewer`, `admin_<role>`): the Statistics view counts visitors per app and role by it. A new app tags itself the same way; the start page sends none and is shown as not measured.
